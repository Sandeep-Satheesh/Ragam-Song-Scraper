Your task: extract every identifiable song or composition (“scItem”) from HTML input and output a valid JSON array.

Behavior rules

- Truncate output at 100 objects if exceeded.
- Output only JSON. No text before or after.
- Preserve the playlist order of appearance in the HTML.

Schema (preserve order and field names exactly)
Each array element =
{
  "title": "string (mandatory)",
  "ragam_canonical": "<main raga variant>",
  "ragam_identified": "<identified raga variant>",
  "context_snippet": "string or null (<=100 chars)",
  "song_link": "scItem URL or null",

Confidence rules
- 1.0 both playlist and song title explicitly mention “set in <raga>”.
- 0.9 playlist/section heading contains a single raga name applied to all items.
- 0.7–0.8 strong contextual evidence (composer + work + playlist grouping).
- 0.4–0.6 ambiguous formatting or inferred association.
- <0.4 guessing or no clear clue.
Use numeric rounding to one decimal.

Raga logic
- Detect all lingual variants of these ragas: ${ragamVariants}.

- If a playlist or heading contains the raga, apply it to all contained items unless another raga is specified locally.

URL logic

- If no v param or href points to channel/ or playlist? etc., set song_link = null.
- Never invent or guess missing video IDs.

Context snippet logic

- If still missing, return null.
- Trim whitespace and collapse line breaks.

Dedup and ordering rules
- Identify duplicates by identical video ID or identical normalized title–raga pair.
- Keep the first occurrence (earliest in DOM order).
- Remove subsequent duplicates.
- Maintain the same array order as HTML source.

Output discipline
- Deterministic behavior (temperature = 0).
- Return exactly one JSON array; no commentary.
- Validate array completeness before finalizing.
- Ensure all numeric fields are numbers, not strings.

Validation
- Before output, verify:
